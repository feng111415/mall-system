### 业务验收

- 登录、商品浏览、重复加购、地址新增/修改/默认切换/删除、结算、幂等下单、创建支付、模拟成功、订单查询全链路通过。

- 另一会员查询该订单支付记录返回空集合，未泄露幂等键。
- 将隔离库测试订单推进到第 35 分钟后模拟迟到支付，结果为订单 `CLOSED`、支付 `REFUNDED`、库存预占 `RELEASED`，且存在唯一 `LATE_PAYMENT_REFUND` 补偿任务。

### 数据库与浏览器

- 回滚验证覆盖 `REFUNDED` 数据归一化及新增列、唯一索引、检查约束的撤销。
- Microsoft Edge 订单详情在 1440px 和 390px 视口通过；`scrollWidth` 等于视口宽度，无控制台错误、失败请求或图片加载失败。

### 超时任务回归补充

- 根因：`MallOrderTimeoutTask` 有实现但未注册到 `sys_job`，Quartz 不会自动执行关闭逻辑。
- 修复：新增 V2.8.1 幂等任务迁移，`mallOrderTask.closeExpiredOrders` 每分钟执行一次；回滚后任务数为 0，重新升级后任务数为 1。
- 实测：同一会员的 3 笔过期待付款订单均在调度周期内关闭，其中 2 笔为 `CLOSED + UNPAID`、1 笔为 `CLOSED + FAILED`；3 条预占库存均为 `RELEASED`，进行中待付款订单数为 0。
- 上限回归：该会员随后通过真实 API 成功创建新订单，证明 `CLOSED` 订单不会计入 3 笔未支付限制。

### 审查结论

- 支付时间窗集中在 `MallOrderPaymentWindow`，订单模块通过 `PaymentExpirationPort` 调用支付过期能力。
- 支付行和订单行锁顺序保持为支付后订单，超时任务与支付回调竞态可收敛。
- 迟到支付状态与补偿任务已纳入同一准备事务，即时退款失败时由现有补偿任务重试。
- 模块 1 满足提交条件；后续模块不得在本提交中混入。
