# 若依后台安全启动配置

## 必填环境变量

生产启动前必须由部署平台注入以下变量，不要写入 `application*.yml`、Git 或启动脚本：

```text
RUOYI_TOKEN_SECRET=<至少 64 个字符的随机值>
RUOYI_DATASOURCE_URL=<生产 MySQL JDBC 地址>
RUOYI_DATASOURCE_USERNAME=<生产数据库账号>
RUOYI_DATASOURCE_PASSWORD=<生产数据库密码>
```

如果确实需要启用 Druid 监控（生产默认不允许），还必须提供：

```text
RUOYI_DRUID_USERNAME=<非默认监控账号>
RUOYI_DRUID_PASSWORD=<非默认监控密码>
```

## 安全默认值

生产还必须设置明确的跨域来源，不得使用 `*`：

```text
RUOYI_CORS_ALLOWED_ORIGINS=https://mall.example.com,https://admin.example.com
```

应用默认返回 CSP、Referrer-Policy、Permissions-Policy、同源 frame 保护；HTTPS 请求再返回 HSTS。生产网关仍需负责 TLS 终止、证书和外部安全头策略。

以下开关默认关闭，不要在生产覆盖为 `true`：

```text
RUOYI_SWAGGER_ENABLED=false
RUOYI_DRUID_STAT_ENABLED=false
RUOYI_MYBATIS_MULTI_STATEMENT_ALLOW=false
```

生产建议显式设置：

```text
SPRING_PROFILES_ACTIVE=prod,druid
```

应用启动时会拒绝缺失或过弱的 JWT/数据库配置、默认 Druid 凭据、生产诊断入口和多语句执行。

## 数据库迁移

发布前使用版本化执行器检查并应用待执行迁移：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\invoke-db-migrations.ps1 `
  -Database <目标数据库>
```

密码继续从 `RUOYI_DATASOURCE_PASSWORD` 读取，不会进入进程参数。执行器使用 `mall_schema_history` 保存版本、脚本、SHA-256、执行人、耗时和结果，并通过带过期时间的 `mall_schema_lock` 数据库租约锁阻止跨机器并发发布。

已有商城库首次接入执行器时必须先核实实际数据库版本，再显式使用一次 `-BaselineVersion`。存在商城表但没有历史记录时，执行器默认拒绝迁移；不要通过手工删除历史记录或修改校验和绕过保护。

发布包的 `database/` 目录包含正向迁移、执行器和 `migration-manifest.json`。回滚 SQL 不自动执行；结构异常优先使用后续修复迁移，涉及业务数据回退时必须单独审批。

发布包还必须包含 `ruoyi-admin.jar`、`mall-storefront/` 和 `mall-admin/`。执行 `scripts/rollback.ps1` 只校验发布包完整性，不直接覆盖运行中的文件；部署平台必须在获批后备份当前 JAR/前端产物，替换候选版本，执行健康检查，失败时恢复备份。

## 本地验收

本地测试库可以临时注入 `MALL_SMS_MOCK_CODE=123456`，生产不要设置该变量；未设置时短信服务使用非固定验证码策略。当前验收环境还使用 `SPRING_DATA_REDIS_PORT=28555` 和独立测试库，不能直接复制到生产。
