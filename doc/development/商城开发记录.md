# 商城开发记录

## 第一阶段：工程基线与前后端骨架

### 已确认

- 项目名称：日常商店商城系统
- 业务类型：单商户 B2C 实物商城
- 后端形态：若依模块化单体
- 用户端：Vue 3 + Vite + Pinia + Vue Router 4 + Vant 4
- 管理端：Vue 3 + Vite + Pinia + Vue Router 4 + Element Plus
- 用户端首页：静态模型模板 A（陈列型）

### 遗留问题

- Mock Adapter 目前只用于联调，不代表真实短信、支付或物流成功。
- 用户端和管理端使用 `createWebHistory`，部署 Nginx 时需要配置 SPA fallback 到 `index.html`。
- 用户端 npm 审计提示 2 个 high 风险；管理端提示 1 个 moderate、2 个 high 风险。依赖升级前需要单独评估兼容性，暂不擅自使用 `npm audit fix --force`。
- 真实启动健康接口尚未完成：本机 MySQL 拒绝项目记录的开发凭据 `root/123456`。未修改数据库密码或数据，待本机凭据恢复后执行 `GET /api/mall/health` 验证。

## 第二阶段：用户与商品（2026-07-27 待验收）

> 当前状态：开发完成，代码已提交到 `dev` 分支，等待用户验收。验收通过后再创建版本标签；未验收前不进入库存、购物车、订单或支付阶段。

### 本周已落地

- 会员身份后端半成品：独立 `mall_member`，未复用后台 `sys_user`。
- 会员短信验证码流程：验证码摘要存储、5 分钟有效、60 秒重发间隔、错误次数限制、成功后一次性消费。
- 会员独立 Token：商城会员会话存入 Redis，使用 `mall_member:login:` 前缀，不复用若依后台管理员 Token。
- 会员资料、协议同意、收货地址和后台会员列表接口骨架。
- 商品中心后端半成品：分类、品牌、SPU、SKU、规格、规格值和商品媒体实体、Mapper、Service、公开接口及后台接口。
- 商品保存使用事务；SPU、SKU 采用软删除方向；上架时要求至少存在可用 SKU。
- 新增数据库迁移草稿：`sql/V0.2.0__mall_member_catalog.sql`，包含第二阶段表结构和少量演示数据。
- 用户端已接入验证码登录、分类/搜索、商品列表和 SKU 详情页面；售罄 SKU 禁止加购。
- 管理端已增加会员、分类/品牌路由和页面，商品页正在替换为 SPU/SKU 管理页面。
- 管理端已接入若依账号密码 + 图形验证码登录、后台 Token、登录守卫和退出登录；商城会员 Token 不能进入管理端。
- 管理端商品、分类、品牌和会员接口已补齐 RBAC `@PreAuthorize` 权限及操作日志注解；迁移脚本新增 19 个权限定义。
- 短信发送增加 Redis 分布式 60 秒锁、手机号/IP 日限额和可注入的开发 Mock 验证码；发送失败会释放锁。
- 商品服务增加 SPU/SKU 编码、价格、库存校验；上架只认可用且未软删除的 SKU；商品管理接口完成权限保护。
- 新增 4 个单元测试，覆盖短信重复点击、商品负价格、负库存和 SPU/SKU 保存。
- 用户端和管理端 Vite 开发代理已分别配置为 `/api -> 8080`、`/admin-api -> 8080`，修正 API 前缀重复问题。
