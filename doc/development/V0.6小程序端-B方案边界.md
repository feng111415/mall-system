# V0.6 小程序端 B 方案边界

日期：2026-08-06

## 已确认

- 下一版本 V0.6 引入商城小程序端；V0.5 的剩余模块不插入小程序实现。
- 采用 B：独立小程序工程，避免把平台条件编译代码混入 `mall-storefront`，保持现有 H5 工程结构清晰。
- 小程序与商城 H5 共享现有 `/api/mall/**` 接口契约、会员 Bearer Token 规则、订单/支付/物流/售后状态和权限边界。
- 后端继续保持模块化单体与 `Controller -> Service -> Mapper -> MySQL` 分层，不为小程序另建一套业务服务。
- 小程序只负责平台适配、页面展示和交互状态；业务规则仍由商城后端服务端执行。

## 工程边界

```text
mall-miniprogram/             独立小程序端（本模块新增）
mall-storefront/              现有 Vue 3 H5，不混入小程序条件编译
mall-business/                共享商城业务 API 与会员身份规则
```

小程序端不得复制订单金额、库存扣减、支付时限、售后金额计算或权限判断。需要新增平台能力时，通过既有应用 Port/Adapter 接入，不能在页面中直接写 SQL 或跨模块业务规则。

## 实施顺序

1. 先输出小程序首页、商品列表、商品详情、购物车、订单、消息、个人中心的静态模型，确认信息层级和底部 TabBar。
2. 确认小程序页面壳、登录态恢复、请求封装、错误/空状态和安全区适配。
3. 接入真实 `/api/mall/**` 接口，优先完成登录、首页、商品详情和订单查询的纵向切片。
4. 使用开发验证码 `123456` 完成真实登录链路，再验证订单、消息和售后状态展示。
5. 在微信开发者工具（或等价小程序运行环境）检查真机尺寸、触控区域、返回行为和网络失败反馈；通过后独立提交 Git。

## 暂不擅自决定

- 小程序实现技术（原生 WXML、uni-app、Taro 等）待技术可行性检查后确认。
- 首页主视觉、字体、颜色、动效和 TabBar 图标沿用已确认的 C1+ 风格，但具体页面静态模型需先给用户确认。
- 微信授权、手机号快捷登录、支付和订阅消息等平台能力，分别在对应纵向切片中确认，不提前扩大本模块范围。
