# V0.4 模块 3：商品与库存运营中心设计

## 范围

本模块建立在现有若依后台和 `mall-business` 商品/库存模块上，增加商品与库存的统一只读运营入口，并补齐现有 SKU 和库存边界。模块不复制订单、物流、售后或支付写操作。

## 运营入口

```
商城运营
└── 商品与库存
    ├── 商品库存中心（本模块新增，只读汇总）
    ├── 商品管理（既有，商品运营写）
    ├── 分类管理（既有）
    ├── 品牌管理（既有）
    └── 库存管理（既有，仓储履约调整）
```

商品库存中心列表支持 SPU/SKU 编码、商品名称、上架状态和库存状态筛选，展示 SKU 数量、可用库存、锁定库存、已售数量、低库存 SKU 数和缺货 SKU 数。点击商品进入详情，查看 SKU 库存和库存流水入口。

## 库存状态

- `HEALTHY`：所有有效 SKU 均高于各自预警阈值且有可用库存。
- `LOW_STOCK`：存在可用库存不高于预警阈值但仍有库存的 SKU。
- `OUT_OF_STOCK`：存在可用库存为 0 的 SKU。

缺货优先于低库存展示。状态只读计算，不单独持久化，库存快照仍由 `mall_stock` 负责。

## 权限边界

- 运营主管：汇总中心、商品管理、库存查询和库存调整。
- 商品运营：汇总中心、商品维护、库存只读；不能调整库存、发货或退款。
- 仓储履约：汇总中心、库存查询和调整；不获得商品维护权限。
- 客服售后、财务风控：不新增商品库存写权限。

汇总中心只读权限使用 `mall:product-inventory:list` 和 `mall:product-inventory:query`。库存调整仍使用既有 `mall:inventory:adjust`。

## 服务端约束

- 商品编辑保留已有 SKU 主键，更新 SKU 属性时不得删除并重建库存关联。
- 移除 SKU 前检查锁定库存、已售库存和有效库存预占；存在履约数据时拒绝移除。
- 商品维护不再修改已有 SKU 的库存数量；库存初始值只在新 SKU 创建时写入，后续统一走库存调整服务。
- 低库存筛选在 SQL 查询阶段执行，分页总数与结果一致。
