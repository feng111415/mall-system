## 已修复问题

### P0：图形验证码答案直接返回客户端（已修复）

`POST /api/mall/member/sms-challenge` 已不再返回 `targetX`，正确位置仅保存在服务端。接口现在返回随机 PNG 场景图、原图裁剪拼图块、挑战标识、初始位置和位置比例；验证票据继续绑定手机号、设备和 IP，保持 120 秒有效、一次性消费和最多 5 次失败限制。

修复回归：验证码服务测试 `5/5`、后端全量测试 `197/197`、商城生产构建和业务全链 E2E 通过；Edge 桌面和移动视口已完成两轮随机挑战、短信发送与登录验证。

### P0：生产默认密钥和凭据（已修复）

JWT 密钥、数据库连接、Druid 账号、钢琴门户码和开发短信 Mock 码均已改为环境变量；Druid 多语句执行和生产 Swagger/Druid 诊断入口默认关闭。新增启动校验：JWT 密钥少于 64 个字符、必需连接参数缺失、默认 Druid 凭据、生产开启诊断入口或开启多语句时拒绝启动。

真实验证：缺少 `RUOYI_TOKEN_SECRET` 的新包启动失败；注入安全环境变量后启动成功，`/v3/api-docs`、`/swagger-ui.html` 和 `/druid/index.html` 均无对应资源。

### P1：HTTP 错误状态码统一（已修复）

新增统一响应处理，将旧有 `AjaxResult.code` 中的 `400-599` 同步为真实 HTTP 状态；成功和业务警告 `601` 保持 HTTP 200，JSON `code/msg` 结构不变。认证入口返回 401，越权返回 403，参数/方法/媒体类型/路由异常分别返回 400/405/415/404，未知运行时异常返回 500；不存在订单详情明确返回 404。

回归验证：`HttpStatusResponseContractTest` 3 项通过；新 JAR 在测试环境启动后，匿名购物车、失效商城令牌、岗位越权、不存在订单、诊断入口和不支持方法分别实测为 401/401/403/404/404/405，健康接口为 200；商城端 E2E 18 项全部通过。

## 阻断问题（按优先级）

### P1：迁移重复执行不幂等

重复执行 `sql/V2.0.0__mall_risk_governance.sql` 报 `Duplicate column name 'risk_status'`。首次从基线升级到 V2.25.2、回滚并再次升级均通过，但缺少统一版本历史或脚本幂等保护，重复部署可能中断。

`mall-storefront`：`npm audit` 报 3 个 high、1 个 moderate；`ruoyi-ui`：9 个 critical、31 个 high、63 个 moderate、10 个 low。若依问题主要来自旧版 Vue CLI/Webpack 构建链，仍需制定升级或构建隔离计划。

## 非阻断不足与测试空白

- 本轮设备多端接口未再次快速压测，因为同一手机号 60 秒重发限制生效；此前交接记录已有 3 手机 + 2 电脑保持 2 移动 + 1 桌面、旧会话 401 的真实证据。
- HTTP 响应未统一返回 CSP、HSTS、Referrer-Policy 等安全头；当前为本地 HTTP 验收，生产应由网关/应用补齐。
- 受保护的未知商城 API 在匿名请求时会先经过认证过滤器并返回 401；公开静态/诊断资源不存在时已实测返回 404。若需对受保护未知路径也统一为 404，需要单独调整安全过滤器与路由匹配顺序。
- 头像超大文件、恶意压缩图片和路径穿越专项请求尚未形成独立自动化报告；代码已有 5MB、格式、尺寸和重编码校验。

## 建议整改顺序

1. 引入迁移版本历史/幂等执行器，补充全量重复升级测试。
2. 分阶段升级商城端和若依端依赖，优先处理 high/critical，重新构建并复测。
3. 补齐头像专项和设备上限自动化后，再进行安全复验和 Git 发布签署。
