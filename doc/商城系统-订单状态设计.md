# 商城订单状态设计

## 订单主状态

| 状态 | 含义 | 允许进入 |
| --- | --- | --- |
| `PENDING_PAYMENT` | 订单已创建，库存尚未预占或已预占，等待支付 | `PENDING_SHIPMENT`、`RISK_REVIEW`、`CANCELLED`、`CLOSED` |
| `RISK_REVIEW` | 命中可疑规则，等待风控审核 | `PENDING_PAYMENT`、`CLOSED` |
| `PENDING_SHIPMENT` | 支付成功，等待发货 | `SHIPPED`、`CANCELLED` |
| `SHIPPED` | 已发货，等待收货 | `COMPLETED`、`AFTER_SALE` |
| `COMPLETED` | 已完成 | `AFTER_SALE` |
| `AFTER_SALE` | 售后处理中 | 暂无自动流转 |
| `CANCELLED` | 主动取消或后台取消 | 终态 |
| `CLOSED` | 超时关闭、风控拒绝或系统关闭 | 终态 |

## 支付状态

订单状态和支付状态分开保存。支付状态使用 `UNPAID`、`PAYING`、`PAID`、`FAILED`、`REFUNDING`、`REFUNDED`，不能用订单状态推断支付结果。

## 核心规则

1. 订单主记录、订单明细和商品快照在同一个本地事务中创建。
2. 订单明细保存商品名称、SKU 编码、规格、图片、单价和数量，后续商品修改不能改变历史订单。
3. `member_id + idempotency_key` 唯一，重复提交只返回首次订单，不创建第二笔订单。
4. 每次状态变化必须写入 `mall_order_operation_log`，记录前状态、目标状态、操作人和请求追踪号。
5. `CANCELLED` 和 `CLOSED` 是终态，不能通过普通状态更新重新打开。
6. 库存预占、释放和支付确认将在后续订单服务步骤接入 `InventoryPort`。
