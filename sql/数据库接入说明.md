# 本机数据库接入说明

## 1. 数据库连接

- 主机：`127.0.0.1`
- 端口：`3306`
- 用户名：`root`

数据库密码只通过当前进程的 `RUOYI_DATASOURCE_PASSWORD` 注入，不要写入 SQL、YAML、Git 或命令行参数：

```powershell
$env:RUOYI_DATASOURCE_PASSWORD='<从安全凭据存储注入>'
```

## 2. 初始化数据库

在 Navicat 里打开查询窗口，先执行：

```sql
create database if not exists `ry-vue` default character set utf8mb4 collate utf8mb4_general_ci;
use `ry-vue`;
set names utf8mb4;
```

新库先按顺序导入基础若依结构：

1. `ry_20260417.sql`
2. `quartz.sql`

基础结构完成后，使用版本化执行器应用商城迁移，不要在 Navicat 中逐个重复运行 `V*.sql`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\invoke-db-migrations.ps1 `
  -Database <数据库名>
```

执行器会创建 `mall_schema_history`，按语义版本排序、记录 SHA-256、跳过已应用版本，并通过 `mall_schema_lock` 数据库租约锁阻止并发迁移。回滚脚本不会被自动执行。

## 3. 已有数据库建立基线

已有商城表但没有 `mall_schema_history` 时，执行器会直接拒绝运行。必须先核对数据库实际版本，再显式建立基线。例如当前独立测试库已验证到 `2.25.2`：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\invoke-db-migrations.ps1 `
  -Database mall_migration_test_20260728 `
  -BaselineVersion 2.25.2
```

`-BaselineVersion` 只登记该版本及之前脚本，不执行 SQL；不得凭猜测用于生产库。基线后再次运行不带该参数的命令即可验证无待执行迁移。

## 4. 启动前检查

后端启动前需要确认：

- MySQL 已启动，Navicat 能连接 `127.0.0.1:3306`
- 目标数据库已存在，基础若依脚本和版本化商城迁移均已完成
- `mall_schema_history` 没有 `success=0` 记录，已应用脚本校验和未发生变化
- Redis 已启动，地址是 `127.0.0.1:6379`

若依默认账号：

- 用户名：`admin`
- 密码：`admin123`
